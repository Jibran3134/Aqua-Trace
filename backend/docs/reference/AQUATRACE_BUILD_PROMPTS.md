Paste order: **Section 1 (Master Context)** at the start of every coding-assistant session, then **one task prompt at a time** from Section 4. Do not paste the whole file into one prompt; small, testable tasks produce better code.

> Verify these three things in the first 20 minutes (they are the ones most likely to differ on your machine):

## 1. MASTER CONTEXT PROMPT (paste first, every session)

```
You are a senior engineer helping a 4-person team build the MVP of "AquaTrace" in a 4-hour hackathon.

PRODUCT
AquaTrace is a decision-support system for water utilities. It infers the likely location of a hidden leak in a water distribution network from a small number of pressure sensors, then runs an investigator agent that ranks candidates, plans a crew inspection route, and re-ranks after the crew reports "nothing found here". It also states honestly when evidence is insufficient and recommends where to add a sensor.

NON-NEGOTIABLE PRINCIPLES
1. Detection must be NON-CIRCULAR. Ground truth is generated by real hydraulic simulation (WNTR/EPANET-style physics) under conditions that differ from the detector's assumptions: random leak size, demand multiplier (+-10%), and sensor noise. The detector never sees the truth.
2. The truth leak location is ONLY returned by GET /scenario/{id}/reveal. No other endpoint, log line shown in the UI, or response may contain it.
3. The LLM never invents facts. It can only call tools. Every number and node ID in the final answer must come from tool outputs. If the LLM fails, a deterministic scripted investigator produces the same flow.
4. Scores are "relative scores", never "probabilities" or "confidence".
5. Every user-facing number is labeled measured / simulated / assumed.
6. Graceful degradation: no unhandled exceptions reach the UI. Every failure produces a readable message and a next action.
7. MVP first. Do NOT build: authentication, a database, Docker, live maps, multi-leak detection, time-series detection.

STACK (all free)
Backend: Python 3.11, FastAPI, uvicorn, pydantic v2, wntr, numpy, scipy, networkx, httpx, python-dotenv, pytest.
Frontend: React + Vite + TypeScript + Tailwind + Cytoscape.js (fallback: Streamlit + Plotly if told to).
LLM: OpenAI-compatible chat-completions with tool calling, provider list from .env (Gemini and Groq OpenAI-compatible endpoints), temperature 0, 8 s timeout, max 6 agent steps, fallback to scripted investigator.
Network: Net3.inp (WNTR example network) copied to backend/data/. Pressure-dependent demand, single steady-state snapshot (t=0) used everywhere; document it in the README.

REPO LAYOUT
aquatrace/
  contracts/api.md
  mocks/*.json
  backend/ main.py sim.py signatures.py detect.py scenarios.py tools.py agent_scripted.py agent_llm.py evaluate.py placement.py repair.py config.py
           data/Net3.inp  cache/  tests/
  frontend/ (Vite app)
  .env.example  README.md  requirements.txt (pinned)

CONVENTIONS
- Type hints and docstrings on public functions. Pydantic models for all request/response bodies.
- Deterministic randomness: every random choice takes a seed.
- No global mutable state except the in-memory SCENARIOS dict in main.py (document it).
- Sync FastAPI endpoints (def, not async) because WNTR is CPU-bound.
- CORS enabled for http://localhost:5173.
- Log to stdout; never log API keys.
- Small functions, pure where possible, unit tests for pure functions.

DEFINITION OF DONE (every task)
Runs from a clean checkout; acceptance tests pass; no new unhandled exceptions; edge cases listed in the task are handled; merged to main.
```

## 3. `contracts/api.md` (create this first; it is the source of truth)

```
GET  /health                      -> {"status":"ok","signatures_ready":bool}
GET  /network                     -> {nodes:[{id,x,y,type}], pipes:[{id,from,to,length}], default_sensors:[id]}
POST /scenario/leak               body {seed?:int, size?:"small|medium|large", noise?:"low|mid|high", sensors?:[id], k?:int}

POST /agent/step                  body {scenario_id, mode?:"auto|scripted|llm"}
                                  -> {events:[{step, type:"thought|tool_call|tool_result|recommendation|abstain|final", name?, args?, result?, text?}],
                                      source:"llm|scripted", recommended_node?:id, route?:[id], state:"investigating|resolved|abstained"}
POST /field/result                body {scenario_id, node, found:boolean}
                                  -> {state:"investigating|resolved", ranking:[{node,score}]}

GET  /eval                        -> precomputed evaluation JSON (see Task T11)
POST /sensors/place               body {k:int} -> {sensors:[id], curve:[{k, top1, top3}]}          (stretch S1)
POST /repair/optimize             body {budget_pkr, candidates:[{node, est_leak_lps, repair_cost_pkr}]} -> {...}   (stretch S2)
```

Error format everywhere: `{"error":{"code":"...","message":"human readable","hint":"what to do next"}}` with proper HTTP status (404 unknown scenario, 422 bad input, 503 signatures not ready).

Create `mocks/` JSON files for every response above (realistic IDs from Net3).

### T1: Simulation wrapper (P1, 0:20 to 0:50)

```
Task T1: backend/sim.py, hydraulic simulation wrapper around WNTR.

Requirements
- base_model(): load Net3 once (lru_cache), set wn.options.hydraulic.demand_model = "PDD" and wn.options.time.duration = 0 (single snapshot). If duration=0 fails in the installed WNTR version, set 3600 and take the first row; document the choice.
- run(leak_node=None, leak_area=None, demand_mult=1.0) -> (pressures: pd.Series indexed by node id, leak_flow_lps: float|None)
  * deepcopy the base model per run (never mutate the cached one).
  * apply wn.options.hydraulic.demand_multiplier = demand_mult (if the attribute is missing in this version, scale each junction's base demand instead).
  * if leak_node: wn.get_node(leak_node).add_leak(wn, area=leak_area, discharge_coeff=0.75, start_time=0). Leaks require the WNTR simulator: wntr.sim.WNTRSimulator(wn).run_sim().
  * return pressures at t=0 from results.node["pressure"]; leak flow from results.node["leak_demand"] if present, else compute with the orifice equation Cd*A*sqrt(2*g*P) using the node's pressure.
- candidate_nodes(): junctions only (exclude reservoirs and tanks).
- graph(): networkx undirected graph from wn.get_graph() with pipe length as edge weight where available.
- network_payload(): nodes (id, x, y from node.coordinates, type) and pipes (id, from, to, length) for GET /network.

Calibration (do this, print the table, and paste it into the README)
- For the 3 sizes in config, simulate a leak at 5 random junctions and print the pressure drop at the 10 nearest junctions and leak flow in L/s. Adjust LEAK_AREAS_M2 so "small" gives a clearly measurable drop at the nearest sensor (> about 0.3 m) and "large" does not crash the solver.

Edge cases
- Non-convergence or negative pressures: catch, retry once with half the leak area, otherwise raise SimulationError (caught by callers; scenario is skipped and counted).
- Never mutate the shared base model.
- Zero-demand junctions are valid leak candidates.
- Pressure Series must not contain NaN for candidate junctions; assert in tests.

Acceptance tests
- run() with no leak returns pressures for every junction in under about 2 s.
- run(leak_node=X, leak_area=medium) lowers pressure at X versus no-leak.
- Two consecutive runs with the same inputs return identical output (determinism).
- candidate_nodes() excludes reservoirs and tanks.
```

```
Task T2: backend/signatures.py.

Build the leak signature library: for each candidate junction c, simulate a REFERENCE_SIZE leak and store S[:, c] = pressure_with_leak - baseline_pressure for ALL nodes (shape: n_nodes x n_candidates). Also store baseline P0 (no leak, demand_mult=1), reference leak flow in L/s per candidate, node order, candidate order.

Acceptance tests
- First build completes (print elapsed time), second startup loads from cache in under 1 s.
- S has no NaN; every column has negative values near its candidate.
- Corrupting the cache file triggers a rebuild, not a crash.

### T3: Scenario generator and detector (P1, 1:15 to 1:45)

```
Task T3: backend/scenarios.py and backend/detect.py.

scenarios.py
- make_scenario(seed, size=None, noise=None, sensors=None, k=DEFAULT_SENSORS_K) -> ScenarioRecord with:
  true_leak_node (random candidate), true_size (random from sizes if None), demand_mult in DEMAND_MULT_RANGE (random), noise_sigma, pressures_all (simulated with leak, noise-free), sensors, readings (pressures at sensors + Gaussian noise, seeded), and a stored rng seed.
- make_no_leak_scenario(seed, noise) for measuring the noise floor.
- default_sensors(k): farthest-point sampling by graph distance over junctions (deterministic, spread out). Used until placement (S1) exists.
- observe(pressures_all, sensors, sigma, seed): applies noise and optional sensor dropout (set to None).
- Store pressures_all so sensors can be changed offline for evaluation without re-simulating.

detect.py
- residual r = readings[sensors] - baseline[sensors]. Drop sensors whose reading is None (offline sensor). Apply centering if enabled (to r and to signature rows alike).
- For every candidate c: s = S[sensors, c]; alpha = max(0, (s.r)/(s.s + 1e-12)) (least-squares leak-size ratio); err = || r - alpha*s ||^2.
- Relative score = softmax(-err / tau), tau tuned on VALIDATION seeds only (store in config), est_leak_lps = alpha * reference_flow[c].
- Return top_k candidates with adjacent pipes (from the graph) plus evidence: residual_norm, noise_floor, margin_top1_vs_top2 (score ratio).
- noise_floor: computed once from 30 no-leak scenarios with random demand multiplier and the scenario's noise level: the 95th percentile of ||r||. Cache it per (k, noise) pair.
- Status "insufficient_evidence" when residual_norm < noise_floor OR fewer than 2 live sensors; include a human-readable note.
- Ties: scores within 1% share a "tie_group" id (UI groups them).

Edge cases
- All sensors offline: status insufficient_evidence, note "no live sensors".
- alpha clipped at 0 means the candidate explains nothing; its error equals ||r||^2.
- Never expose true_leak_node from detect().
- Seeds reproducible: same seed gives identical scenario and identical detect() output.

Acceptance tests
- On 10 fixed seeds with default sensors and noise "mid": the true node is in the top 3 at least 6 times (if not, debug before continuing; do not move on).
- A no-leak scenario returns insufficient_evidence in at least about 90% of 30 seeds.
- A scenario with every sensor set to None does not crash.
- Same seed gives byte-identical JSON.
```

### T7: Agent tools (P2, 0:20 to 1:30, on mock data first)

```
Task T7: backend/tools.py. Pure, validated functions that operate on a ScenarioState. Each returns JSON-serializable dicts and raises ToolError(message) on invalid input; ToolError messages are shown back to the LLM.

Tools
1. rank_candidates(state, top_k=3) -> [{node, score, est_leak_lps, adjacent_pipes}] using current posterior weights; includes evidence and margin.
2. simulate_hypothesis(state, node) -> predicted vs observed residual at each live sensor under "leak at node with estimated size": {node, per_sensor:[{sensor, observed, predicted}], rmse, fit_label}. Use the signature (alpha*s) by default; cache; an optional exact=true runs a real WNTR simulation (slow, off by default).
3. plan_inspection(state, nodes, depot=None) -> {order:[node], total_length_m, legs:[{from,to,length_m}]} using nearest-neighbour ordering over shortest path lengths in the graph. Depot defaults to the node nearest the first reservoir.
4. record_field_result(state, node, found) -> posterior update:
     found=true: state.resolved = True; return {"closed": True} (never reveal truth).
     found=false: weight[node] *= MISS_PROB (imperfect inspection; do NOT zero it), renormalize, return new ranking.
   Idempotent: repeating the same report changes nothing.
5. recommend_sensor_addition(state) -> best non-sensor node that maximizes |s_a[n] - s_b[n]| between the top two candidates a and b, only when status is insufficient or margin_top1_vs_top2 < 2; otherwise returns {"recommended": null, "reason": "..."}.

Validation
- Every node argument must exist in the network and (where relevant) be a candidate; otherwise ToolError("unknown node X; valid examples: ...").
- top_k clipped to [1, 10].

Also produce TOOL_SCHEMAS: the OpenAI-style JSON schemas (name, description, parameters) for the 5 tools, used by the LLM agent.

Edge cases: node already inspected (return a note, do not re-recommend); all candidates excluded (posterior sums to about zero: reset to the initial posterior and return state "abstained" with a note); concurrent calls on the same state (lock).
Acceptance tests (pytest, no LLM): after three "not found" reports on the top candidates, the ranking changes and the excluded nodes stay low but non-zero; reporting found=true resolves; invalid node raises ToolError.
```

### T8: Scripted investigator (P2, 1:30 to 2:00)

```
Task T8: backend/agent_scripted.py: deterministic investigator that produces the SAME event shape as the LLM agent.

Flow per /agent/step call (one "turn"):
1. thought: "Ranking candidates from sensor residuals." -> tool_call rank_candidates -> tool_result.
2. If status is insufficient_evidence or margin < 2: tool_call recommend_sensor_addition -> event type "abstain" with the recommendation and state "abstained". Stop.
3. Otherwise: tool_call simulate_hypothesis(top1) -> tool_result.
4. tool_call plan_inspection(top 3 nodes) -> tool_result.
5. recommendation event: "Inspect node X first (route: ...)" with recommended_node and route. State stays "investigating".
After POST /field/result found=false, the next /agent/step re-ranks and recommends the next best node; found=true ends with a final event summarizing the investigation (inspections used, route length) using ONLY tool outputs.
Templates produce all text; numbers come from tool results.
Edge cases: no new candidates (abstain with a note); same node recommended twice (skip inspected nodes); step cap.
Acceptance: a scripted full investigation runs offline with all LLM keys removed.
```

### T9: LLM agent with fallback (P2, 2:00 to 2:30)

```
Task T9: backend/agent_llm.py.

- Provider list from .env (LLM_1_*, LLM_2_*): OpenAI-compatible POST {base_url}/chat/completions with tools=TOOL_SCHEMAS, temperature 0, timeout LLM_TIMEOUT_S. Try provider 1, on 429/5xx/timeout/invalid tool JSON try provider 2, then raise LLMUnavailable -> main.py falls back to the scripted investigator and reports source="scripted".
- Loop: max MAX_AGENT_STEPS tool-call rounds per /agent/step. Each tool call is validated and executed via tools.py; ToolError text is returned to the model as the tool result so it can self-correct once.
- System prompt (use exactly this idea):
  "You are the AquaTrace investigator. You help a water utility find a hidden leak. You may ONLY use the provided tools; never guess node ids or numbers. Start with rank_candidates. If evidence is insufficient or the top two candidates are close, call recommend_sensor_addition and stop. Otherwise call simulate_hypothesis on the top candidate, then plan_inspection for the top three, then recommend one node to inspect. Never claim certainty; scores are relative scores. Keep any narrative under 60 words and do not state numbers yourself; the system inserts them."
- Final answer assembly: the structured result (recommended_node, route, ranking, evidence) comes from tool outputs. The model only writes a short narrative. Guards: every node id in the narrative must exist in the network; every number in the narrative must appear in some tool result; otherwise replace the narrative with the template text. Always return events in the contract format.
- DEMO_MODE=true skips the LLM entirely.
Edge cases: hallucinated node id; infinite loop (step cap); empty model reply; provider returns text instead of a tool call; JSON arguments with extra fields; rate-limit during the demo (fallback must be silent for the user, with a small "scripted mode" badge).
Acceptance tests: with valid keys, a full investigation completes; with keys removed or LLM_ENABLED=false, the scripted flow completes; with a deliberately malformed provider response (mock), fallback triggers; narrative guard rejects an injected fake node id.
```

### T12: Sensor placement, stretch S1 (P4 or P1, 2:30 to 2:50 only if MVP-1 is solid)

```
Task T12: backend/placement.py and POST /sensors/place.
- Greedy forward selection: start empty; at each step add the node that maximizes the number of candidate pairs (i, j) whose signature difference norm over the chosen sensors exceeds delta = 2 * sigma_eff (sigma_eff from the noise level plus the empirical demand-mismatch residual). Tie-break by farthest graph distance from existing sensors.
- For k = 1..12 compute top-1 and top-3 accuracy on the cached VALIDATION scenarios (re-use pressures_all, change sensors only). Return the curve and the chosen sensors for the requested k.
